# 既知の問題・未確定事項

## ステータス

このバックテストは作業途中であり、現在の損益、CAGR、最大ドローダウン、売買回数、利益確定履歴を戦略評価に使用してはならない。コードが実行できることと、依頼者が把握している基準値に一致することは別である。現在は後者の照合が完了していない。

## P0 — 結果を無効にし得る問題

### 1. 日次CAPEの値が基準値と照合されていない

現在は次式で日次CAPEを推定している。

```text
E10_m = ShillerPrice_m / ShillerCAPE_m
DailyCAPE_t = SPX_Close_t / E10_(m-1)
```

この構造自体は採用仕様に沿うが、次が未解決である。

- Shiller月次値が翌月最初の営業日に利用可能だったと仮定しており、実際の公表日・公表ラグを再現していない。
- 古い期間はShiller系列、直近延長部分はMultpl CAPEとYahoo SPX月平均を組み合わせており、PriceとCAPEの定義・丸め・更新時刻が同一とは限らない。
- earnings、CPI、CAPEの事後改訂を当時利用可能だった値として再現していない。
- 月次PriceがShillerの月平均と完全一致するかを全期間で保証していない。
- 2026-05-13など、依頼者が把握している特定日のCAPE、Deviation、Z、CDF値を固定入力で再現するゴールデンテストがない。

したがって、生成される `CAPE_daily` は現段階では推定系列であり、正確なPoint-in-Time CAPEではない。

### 2. 10年ローリング値の基準照合が不足している

月次の共通計算は次の二段階である。

```text
mean1_t = mean(x[t-119:t])
deviation_t = (x_t - mean1_t) / mean1_t
mean2_t = mean(deviation[t-119:t])
std2_t = sample_std(deviation[t-119:t])
z_t = (deviation_t - mean2_t) / std2_t
risk_t = NormalCDF(z_t)
```

日次判定は「直前119か月＋当日値」で当日を含む120観測を作る。しかし、以下をまだ保証していない。

- 依頼者提示のPandas計算と、固定した同一データ・同一日付で列ごとに一致すること。
- 欠損月がある場合にも「119観測」ではなく連続した「119暦月」になっていること。現コードの `.tail(119)` は欠損月を飛ばす。
- 二段目へ入れる過去Deviationの時点構成が、依頼者の期待する日次再計算と完全に同じこと。
- 月初のE10更新による段差がZスコアへ与える影響。
- 入力値、rolling mean、Deviation、Deviation mean/std、Z、CDFの全中間値を保存して照合できること。

また、二段ローリングは最初の有効Zまで実質約239か月を必要とする。これはPandas式の結果だが、利用開始日の意図を再確認する必要がある。

### 3. 買い推奨度が0–1ではなく0–2になっている

現コードは次式を使用する。

```text
recommendation = 2 * NormalCDF(-Z_expensive)
```

これは中立時を1にするための実装上の仮定であり、依頼者が示した「最終的に0から1へ変換される値」をそのまま買い推奨度に使う設計とは一致しない可能性が高い。0–1を採用するなら候補は次式である。

```text
recommendation = NormalCDF(-Z_expensive)
```

この差は通常購入額を最大2倍変えるため、資金推移と全成績を無効にし得る。確定前に結果を比較してはならない。

### 4. VIXイベント開始時の追加売却が未実装

合意された「イベント開始時点のターゲット超過分の50%を追加で売り、待機金を再装填する」処理が現コードにない。現状はイベント開始時の現金を記録するだけである。

```text
event_budget = event_start_cash
one_tranche = event_budget / 3
```

そのためイベント購入額、待機金、TQQQ保有率、後続の利益確定額が意図と異なる。

### 5. 利益確定の再装填条件が未確定

現コードは各資産のZが `0以下` になった時点で、+1σ、+2σ、+3σの全ティアを再装填する。一方、会話で示された「シグマの真ん中まで戻ったらリセット」が何を意味するかはコード化されていない。

候補には、各ティアの中間点（+0.5、+1.5、+2.5σ）による個別再装填、または0σによる全再装填があり、結果は大きく異なる。現状の0σ全リセットは暫定仮定である。

### 6. 利益判定がポートフォリオ全体ではなく取得ロット単位

依頼者の認識は「ターゲット超過分は理論上含み益であり、現在価値が取得価格合計を上回る」である。現コードは、売却時点で売値を上回る取得単価のロットを一切売らず、利益のあるロットだけを順番に売る。

このため、ポジション全体では利益でも一部ロットが含み損なら、+3σでもターゲットまで戻らない場合がある。判定を「総時価 > 総取得原価」とするか、ロット単位とするかを確定する必要がある。

## P1 — 売買額・シグナル履歴を変える問題

### 7. 複数ティア同日到達時の仕様と文書に不整合がある

現コードは前日から当日に+1σ、+2σ、+3σをまとめて跨いだ場合、1、2、3の各売却を順番に翌営業日へ発注する。これは「各水準でそれぞれ売る」という依頼者の指摘を反映した動作である。

ただし旧仕様書には「最高ティアだけを実行する」という記述が残っている可能性があり、コードと文書を一本化する必要がある。また同じ執行日の各売却は、直前の売却後に残った超過額を再計算するため、シグナル日の超過額に対する単純な25%＋50%＋100%ではない。

### 8. 利益確定は日次だが、価格とシグナルの時点監査が不足

利益確定判定は日次で、シグナル翌営業日の始値で実行する。月次購入とは分離されている。ただし以下が未監査である。

- 日次Zの最初の有効日に既に+1σ以上だった場合、前日Zがないため売却しない。
- シグナル日から翌共通取引日までに資産別休場や欠損がある場合の扱い。
- 売却量はシグナル時ではなく翌日の始値で超過額を再計算する。
- 以前報告した利益確定回数は、CAPEとローリング値の確定前に算出したため信頼できない。

### 9. 通常購入の現金保持が形式的

通常購入額は次式である。

```text
gap_i = max(0, target_weight_i - current_weight_i)
buy_i = total_equity * gap_i / 18.3 * recommendation_i
```

合計購入額が現金以上なら比例縮小し、`cash * (1 - 1e-9)`まで使用する。このため数学的には正の現金が残るが、経済的には待機金がほぼゼロになる可能性がある。「有限時間では常に意味のある待機金が残る」という意図を満たす下限ではない。

また18.3か月は固定時定数だが、係数自体は総資産、現在比率、ターゲット差、現金により毎月変動する。この区別を出力で監査できるようにする必要がある。

### 10. VIXイベント月の月次購入停止条件が完全ではない

現コードは、VIX購入シグナルが存在する月、または月末時点でイベント中の月を停止対象とする。イベントが月内に開始・終了し、購入シグナルがなかった場合などは停止対象から漏れる可能性がある。「VIXイベントが起きた月」の定義をイベント開始、イベント継続、実際の購入発生のどれにするか固定する必要がある。

### 11. GLDとTLTの推奨度は資産固有価値ではない

現在は次の代理変数だけを使用する。

- GLD: `Z_expensive = -Z_DXY`
- TLT: `Z_expensive = -Z_30Y_yield`

DXYだけで金の買い場を、30年金利だけでTLTの買い場を完全に表す統計的根拠はまだ検証・文書化されていない。相関の符号、ラグ、局面依存性、構造変化を検証する必要がある。

### 12. 対数変換後の相対乖離式に数理上の注意がある

DXYと30年金利は対数変換後に、さらに次式を適用している。

```text
(log(x) - rolling_mean(log(x))) / rolling_mean(log(x))
```

これは `log(x / geometric_mean(x))` や、単純なlog値のZスコアとは異なる。特に30年金利では平均log値がゼロへ近づく局面で不安定になり得る。対数変換する合意と、その後にCAPEと同じ相対乖離式を使う合意は分けて検証する必要がある。

## P2 — バックテスト範囲とデータ品質

### 13. 現行ポートフォリオ結果にITバブル崩壊が含まれない

全資産の共通取引日を使うため、GLD設定前を除外し、現行結果は2004年末付近から始まる。疑似TQQQ系列を1999年まで延長していても、60/30/10ポートフォリオの評価にはITバブル崩壊期が入っていない。

ITバブルを含めるには、GLD設定前の金価格代理系列などを別途定義する必要がある。現状の結果を「ITバブルとリーマンを含む全期間検証」と表現してはならない。

### 14. 疑似TQQQは厳密なETF再現ではない

設定前はQQQの日次リターンを単純に3倍して複利化している。これは合意された近似だが、資金調達コスト、信託報酬、先物・スワップ費用、実際の追随誤差を含まない。長期間ほど誤差が累積する。

### 15. 配当と市場データの時点

- Yahooの配当は支払日ではなく主に権利落ち日で現金計上している。
- DXY、30年金利、ETFの休場日差はforward-fillまたは共通日付化で処理される。
- 外部サイトの過去値が更新・訂正されると、同じコードでも結果が変わる。
- 入力データのスナップショットとハッシュを保存していないため、完全再現できない。

### 16. ケリー基準は配分ロジックに実装されていない

TQQQ 60%、GLD 30%、TLT 10%は固定設定である。簡易ケリー20.4%、疑似TQQQ、多変量ケリー、実効レバレッジから60%を導く計算は、現バックテストの入力生成・検証工程に組み込まれていない。したがって60%の根拠をコードから再計算できない。

## 修正前に必要な受入テスト

1. 使用データをCSVで固定し、取得日時、出典、ハッシュを保存する。
2. 指定日について、CAPE、E10、120か月平均、Deviation、Deviation平均、Deviation標準偏差、Z、CDFを手計算表と一致させる。
3. 特に2026-05-13など依頼者が把握する日付をゴールデンテストにする。
4. 月次版と「119完了月＋当日」の日次版を同じ入力から並べ、差の理由を1列ずつ説明する。
5. DXYと30年金利について、raw、log、Deviation、Z、向き反転後Z、推奨度を保存する。
6. 買い推奨度を0–1と0–2の両方で比較し、購入額と待機金推移を確認して正式式を固定する。
7. +1σ、+2σ、+3σの単独到達、同日複数到達、各リセット条件を人工系列で検証する。
8. イベント開始時の超過分50%売却と、固定した待機金3分割を取引台帳で照合する。
9. 利益判定を総取得原価方式とロット方式で比較し、正式方式を固定する。
10. 上記完了後にのみ、利益確定履歴とバックテスト成績を再生成する。
